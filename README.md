## 📖 About The Project

**HEXAI-All-in-One** is engineered to bridge the gap between fragmented artificial intelligence models and developer productivity.

Whether you are looking to orchestrate multi-agent pipelines, leverage state-of-the-art NLP models locally or via cloud wrappers, or script complex data workflows, HEXAI packages it into an accessible, high-performance ecosystem.

<table>
<tr>
<td width="50%" valign="top">

**The problem**

- 🔌 Every AI provider has its own SDK, auth, and quirks
- 🧩 Glue code scattered across scripts, notebooks, and services
- 🐌 Blocking calls and poor async support kill throughput
- 🔐 Sensitive prompts and data leaking to third parties
- 🧱 No shared plugin/tooling layer between projects

</td>
<td width="50%" valign="top">

**The HEXAI answer**

- ✅ One unified orchestration layer for every provider
- ✅ Modular, hot-swappable toolkit plugins
- ✅ Fully async, low-latency execution engine
- ✅ Local-first, privacy-preserving by default
- ✅ Extensible plugin API with first-class DX

</td>
</tr>
</table>

## ✨ Key Features

| | Feature | Description |
|:--:|:--|:--|
| 🚀 | **Unified AI Orchestration** | Connect and switch seamlessly between multiple AI providers and local models. |
| 🛠️ | **Modular Toolkits** | Pre-built plugins and hooks for data scraping, code generation, summarization, and task management. |
| ⚡ | **High Performance & Low Latency** | Optimized architecture designed for asynchronous execution. |
| 🔒 | **Secure & Privacy-First** | Built with strict data handling controls and customizable local-first preferences. |
| 📦 | **Extensible Plugin System** | Easily write custom tools and integrate them directly into your workflow. |

<details>
<summary><b>🔍 Feature deep dive (click to expand)</b></summary>

<br />

**🚀 Unified AI Orchestration**
A single `Orchestrator` entry point normalizes requests across providers. Declare a chain of agents and tools once — swap the backing model without rewriting business logic. Fallback, retry, and rate-limit policies are applied uniformly.

**🛠️ Modular Toolkits**
Tools are self-describing (name, schema, handler). They can be composed into pipelines, called directly from the API layer, or exposed to LLM function-calling automatically via generated JSON schemas.

**⚡ High Performance & Low Latency**
Async-first core built around `asyncio`, connection pooling, request batching, and optional Redis-backed response caching for repeated prompts.

**🔒 Secure & Privacy-First**
- Local-first mode: run entirely offline with local models
- Explicit allow-lists for outbound provider calls
- Secrets loaded from `.env` — never logged, never committed
- Redaction hooks for PII before any egress

**📦 Extensible Plugin System**
Drop a new module into `plugins/` and it is auto-discovered at boot. No core changes, no re-registration boilerplate.

</details>

🚀 Getting Started

Follow these instructions to get a copy of the project up and running on your local machine for development and testing purposes.

Prerequisites

· Python 3.10+ or Node.js 18+ installed, depending on your environment preference
· Docker (optional, for containerized deployments)
· API keys for any cloud providers you intend to use (optional in local-first mode)

Installation

1. Clone the repository

```bash
git clone https://github.com/HexSleuth/HEXAI-All-in-One.git
cd HEXAI-All-in-One
```

2. Configure your environment

```bash
cp .env.example .env
# Edit .env and insert your API keys and configuration parameters
```

3. Install dependencies

```bash
pip install -r requirements.txt

# OR if using npm/pnpm
npm install
```

4. Run it

```bash
python main.py

# OR
npm run start
```

🐳 Docker

```bash
docker build -t hexai-all-in-one .
docker run --env-file .env -p 8000:8000 hexai-all-in-one
```

⚙️ Minimal .env

```env
# ── Runtime ─────────────────────────────────────────────
APP_ENV=development
LOG_LEVEL=info
HOST=0.0.0.0
PORT=8000

# ── Providers (fill in what you use) ────────────────────
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=
HF_TOKEN=

# ── Local-first / privacy ───────────────────────────────
LOCAL_ONLY=false
REDACT_PII=true

# ── Optional infrastructure ─────────────────────────────
DATABASE_URL=postgresql://user:pass@localhost:5432/hexai
REDIS_URL=redis://localhost:6379/0
```

🔐 Never commit your .env. It is already ignored by default — keep it that way.

💡 Usage

The snippets below are illustrative templates. Adjust imports and method names to match the modules in core/ and api/ after you clone.

<details open>
<summary><b>Python — orchestrate a task</b></summary>

```python
import asyncio
from core.orchestrator import Orchestrator
from config.settings import load_settings

async def main() -> None:
    settings = load_settings()

    async with Orchestrator(settings) as orch:
        result = await orch.run(
            task="Summarize the latest commits and open issues.",
            tools=["github_fetch", "summarize"],
            model="default",
        )
        print(result.output)

if __name__ == "__main__":
    asyncio.run(main())
```

</details>

🔌 Plugin System

Adding a tool is a two-step job:

```python
# plugins/example_echo.py
from plugins.base import Tool, ToolResult

class EchoTool(Tool):
    name = "echo"
    description = "Echoes the provided text back to the caller."

    async def run(self, text: str) -> ToolResult:
        return ToolResult(ok=True, data=text)
```

Plugins in plugins/ are auto-discovered at startup — no registration boilerplate required. Expose them to LLM function-calling by adding the tool name to your task's tools list.
